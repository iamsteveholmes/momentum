# Sprint Dossier — sprint-2026-05-25

**Date compiled:** 2026-08-02
**Role:** Evidence dossier for one sprint in the nornspun delivery-discovery investigation (why sprints ship stories but no user-facing feature works end-to-end).

## Executive Summary

- This was a **2-story, docs-only housekeeping sprint** with **zero product-capability stories**. Both stories retired the legacy `_bmad-output/` folder and moved SDRs/knowledge docs into `docs/`. Neither story touched application code (`nornspun-backend` or `nornspun-client`); git log confirms zero commits in either app repo during the sprint window (2026-05-24 → 2026-06-02).
- The sprint's own goal framing (coverage-plan.md, story specs) is explicit tasks/infrastructure language ("migrate SDRs," "retire `_bmad-output/`") — never a user-capability sentence ("a GM can..."). This sprint is not a case of the stories-vs-functionality gap; it's a sprint that never claimed to deliver functionality, and it delivered exactly what it claimed.
- **This is a genuinely durable success**, unusual in this corpus: both stories reached `done`, the rule file (`.claude/rules/no-bmad-output.md`) and the migration hold up unchanged as of 2026-08-02 (10 weeks later) — `_bmad-output/` still contains only empty dirs + a README redirect, `docs/decisions/` still holds the full SDR series through SDR-017.
- Implementation itself was clean: both stories converged in a single dev pass each (150 and 191 turns, zero re-dev, zero abandoned agents out of 61). All sprint friction — 41 of 58 verified findings — lived in the **review/verification layer**, not in coding: absolute grep-gate acceptance criteria with no exclusion lists produced the sprint's only false positive (AC8, wiki-ingest) plus three more false-FAIL re-adjudications.
- A **retro-tooling defect independently confirmed in this investigation**: the audit's own extraction is scoped by file mtime, not sprint/story affiliation — ~70% of the 61 agent summaries and ~42% of the 181 user-message rows are contamination from adjacent sprints (pre-sprint campaign-init walkthrough, next-sprint conduct). One `team-messages.jsonl` row attributed to this sprint is verified (by this dossier, independently) to actually be a different sprint's backend security review (an IDOR finding on a `/heroes` endpoint — nothing to do with `_bmad-output`).
- **Contaminated-but-load-bearing context surfaced in this window**: the corpus captured a developer-led walkthrough (2026-05-19) from the *prior* sprint (campaign-init) that found campaign creation broken on both platforms after that sprint claimed completion, and a 5-phase wizard UI that contradicted stated product intent ("the ONLY requirement is a campaign name"). This is the clearest piece of corroborating evidence in this dossier for the overall mission hypothesis — but it belongs to campaign-init (sprint-2026-05-01 era), not to sprint-2026-05-25, whose own scope never touched product UI.
- Known process defects: `momentum:create-story` was unregistered and planning silently hand-wrote stories instead of halting and flagging (a workflow-fidelity violation); `momentum:code-reviewer` was a stub, causing a ~12h15m pipeline halt; story-file frontmatter bookkeeping (`status: ready-for-dev`) never synced to the `done` index status — and as of 2026-08-02, both story files **still** read `ready-for-dev` with empty Dev Agent Records, confirming the fix recommendation was never applied to these two stories.
- Retro (run 2026-06-12, ~2.5 weeks after sprint close on 2026-05-30) additionally drove a corpus-wide backlog dedup: 31 backlog stories resolved (9 marked obsolete, 6 merged into 2 survivor stories, 16 status-synced to `done` for already-shipped work whose index never transitioned) — this is verified via `backlog-dedup-proposal.md` and the story index.
- All 8 priority action items from this retro were routed to Momentum's own `practice-ledger.jsonl` (verified: 5+ entries present, `source_sprint: sprint-2026-05-25`), not into nornspun's backlog — consistent with this being a pure process-improvement sprint with no product residue.
- Note on file metadata: every file in `.momentum/sprints/sprint-2026-05-25/` shows a filesystem mtime of 2026-07-13, but `git log` on each file shows real authorship dates of 2026-05-26 (specs/coverage-plan/team-composition) and 2026-06-12 (retro/summary/dedup). The Jul-13 mtime is a filesystem artifact (likely a bulk checkout/touch during the later mega-retro) — content and git history are authoritative and were used throughout this dossier.

## 1. INTENT

**Coverage-plan.md** (`.momentum/sprints/sprint-2026-05-25/coverage-plan.md`) frames the sprint under a single integration scenario: *"Full `_bmad-output/` Retirement End-to-End"* — described as "A reviewer confirms the complete retirement by inspecting the final repository state — SDRs at `docs/decisions/`, all other knowledge documents at their `docs/` destinations, `_bmad-output/` empty, BMAD config updated, and wiki-query returning results for migrated content."

**Team-composition.md** lists two stories across two serial waves (`migrate-sdrs-from-bmad-output-to-docs-decisions` Wave 1, `retire-bmad-output-migrate-to-docs` Wave 2, the latter depending on the former), both assigned to `momentum:dev`, both reviewed via `document-review` harness profile (no services required — filesystem-only checks).

**Story framing** (both story specs, `.momentum/stories/*.md`): both use the "As a developer, I want ... so that ..." template, but the "want" clause is explicitly infrastructural: *"I want strategic decision records (SDRs) to live in `docs/decisions/` rather than `_bmad-output/planning-artifacts/decisions/`"* and *"I want `_bmad-output/` to be retired and its contents migrated to their correct locations."* Neither story frames a GM-facing or player-facing capability. The stated trigger was AVFL validation surfacing a gap ("the ios-bringup story was misclassified because the SDR path convention diverges from D6") plus a developer frustration escalation (see below).

**Verdict on intent:** Goal was stated as **infrastructure/tooling** (repo reorganization), not as a user capability. This is a sprint that never claimed to move the product forward for an end user — it claimed to make `docs/` the canonical KB source so agents (not GMs) could find things via `wiki-query`.

**Story 2 (`retire-bmad-output-migrate-to-docs`):** single dev pass, agent-a03a8e, 191 turns, 0 tool errors, ~15 granular git-mv commits for a 71-file migration, AVFL score moved 78→97 after one fix round. ## Counter-evidence & falsifiability

- **This sprint is evidence *against* the "stories over functionality" framing applying universally** — its plan, execution, and outcome are all self-consistent and honest about being infrastructure work; it never dressed up documentation migration as a user capability, and its completion claim ("2/2 done, docs-only, no product defects") matches reality exactly. If the investigation's hypothesis is "sprints systematically claim capability delivery that isn't real," this sprint is a clean counter-example: it claimed capability delivery for *nothing* and delivered *nothing* (correctly, honestly).
- **The clearest evidence for the broader hypothesis found in this sprint's window is not this sprint's own work** — it is contamination from the adjacent campaign-init sprint (a P0 happy-path break and a wizard UI that contradicted stated product intent, both surfaced only by a human-initiated walkthrough, not by automated validation). This dossier attributes that evidence to campaign-init/sprint-2026-05-30, not to sprint-2026-05-25, and a reader should weight it accordingly — it would be a misattribution to cite this sprint as "proof" of the functionality gap.
- **What would prove the "genuinely durable success" framing wrong:** if `_bmad-output/` had silently reaccumulated files after the sprint (it has not, as of 2026-08-02 — verified directly on disk), or if the SDR series had stopped being written to `docs/decisions/` (it has not — SDR-017 is dated 2026-07-09, well after this sprint).
- **What would weaken the "implementation was clean, review layer was the friction" claim:** if raw dev-agent transcripts showed hidden rework not captured in the 150/191-turn counts. This dossier did not read the full raw session JSONL (unavailable — this sprint predates the earliest retained raw transcript, 2026-07-06, per the mission brief); it relied on `agent-summaries.jsonl` counts and the retro audit's synthesis, spot-checked but not fully re-derived from scratch.
