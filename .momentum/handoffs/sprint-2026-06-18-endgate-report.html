01What shipped

The problem it solves. A specialist agent here means a focused AI worker — say, a Kotlin/Compose developer agent — that a sprint can spawn to do a particular kind of work. Until this sprint, Momentum had no way to hand such an agent two things it badly needs: (1) the host project's own conventions, and (2) a map from "the symptom I'm seeing right now" to "the exact query I should run against the project's knowledge base." A knowledge base (KB) is the project's distilled, searchable memory; a wiki-query is the lookup an agent runs against it. Without that map, every specialist agent started each sprint cold — no project conventions, no idea what to look up when it got stuck.

What now exists that didn't before. This sprint lays the foundation for composing such agents — what we call the Gen-2 agent cohort ("Gen-2" = the second-generation, project-aware agents, as opposed to the generic ones). Five new building blocks, plus two engine repairs:

  1. A canonical manifesto format — a standard layout for a per-role-by-domain diagnostic table: a lookup that maps a developer's symptom to the exact wiki-query that answers it. One authoritative spec, so every producer builds the same shape.
  2. A smarter constitution-builder — the tool that writes an agent's constitution (its always-on rules) can now emit three different kinds of output, and no longer leaks per-agent routing into the shared rules.
  3. A canonical wiki-query interface block — the standard, prescriptive way an agent reaches that cold knowledge base, identical in every constitution.
  4. A new build-guidelines skill — the orchestrator that ties the above together: it composes a specialist agent (base body + diagnostic table + domain knowledge) and registers it so a sprint can actually find and use it.
  5. A real first consumer — an actual project constitution for the nornspun project, the first place all this gets used for real.

Plus two conduct-engine repairs surfaced by the 2026-06-14 audit. ("Conduct" is the autonomous build engine that produces this very report.) First, every review finding now gets a stable identity before the auto-fixer touches it. Second, the engine's durable build ledger now deduplicates safely when a build is resumed, so a restarted build never double-counts its findings.

Important caveat — this is the foundation, not the finished cohort. The composition pipeline is wired end to end and works when a developer drives it by hand. But whether a composed agent can reliably be found by a sprint rests on one best-effort step that still needs a single follow-up to be fully deterministic. §06 lays out exactly what's live versus still hollow — read it before you decide, because it bears directly on what approving does.

03Where the build diverged — the high-risk moments

These are the 5 divergences that mattered: places where the first attempt got something wrong that, unfixed, would have caused real harm. Each was caught by the build's own review before anything merged, then fixed and re-verified. Scan the headlines; open any one for the full story — what the piece does, why its guarantee was written the way it was, where reality diverged, the risk that created, and why the resolution is acceptable. Scariest first.

▶The whole "agent cohort" would have registered agents that could never be matched and never assembled — so it would have looked like it worked while delivering nothing at all.
The keystone orchestrator · build-guidelines-skill

What this part does: build-guidelines is the new orchestrator that, for a project, composes a specialist agent and registers it so a later sprint can find and use it. "Register" means writing an entry into agents.json that includes the file patterns the agent owns; "find it" means the resolver later matches a story's touched files against those patterns. This is the entire reason the Gen-2 cohort exists.

Why we wrote a guarantee around it, and why that way: the signature way an orchestrator like this fails is by appearing to succeed — it writes a registration entry, reports "done," and nobody notices the entry is hollow. So the guarantee (G1) was written to demand not just "register an agent" but "register a resolvable one": an agent the resolver can actually match, with a fully-assembled body. The intent was to make the silent-success failure impossible to pass.

Where reality diverged: the first implementation registered composed agents with empty file patterns and never assembled the agent body at all. With empty patterns, the resolver can match nothing — so every sprint would silently fall back to the generic dev agent, exactly as if the cohort didn't exist.

The risk that created, and what catching it removed: the entire sprint's headline capability would have shipped as a convincing illusion — registrations present, agents real on paper, and zero behavioral effect. A developer would build the cohort, see no errors, and quietly get the generic agent forever. Catching it removed a whole-sprint false-success.

Why the outcome is acceptable: the fix delegates composition and registration to the existing agent-builder skill, which populates the file patterns and assembles the full agent file. The IS-1 integration trace re-verified that a well-formed manifesto now produces a resolvable agent. (The remaining best-effort caveat — that pattern derivation is inferred, not schema-guaranteed — is held honestly in §06, not hidden here.)

▶Even after the first fix, the composed agent would have shipped with no diagnostic table at all — the one thing the whole manifesto exists to give it.
Carrying the diagnostic table · build-guidelines ↔ constitution-builder

What this part does: the diagnostic table is the symptom→knowledge-base-query map — the agent's "when I see X, look up Y" guide. build-guidelines is responsible for making sure the composed agent actually carries that table.

Why we wrote a guarantee around it, and why that way: a specialist agent without its diagnostic table is just a generic agent with a project label — it has lost the exact capability the manifesto format was created to deliver. So the contract intends that the composed agent end up holding the manifesto's table verbatim, by whatever route.

Where reality diverged: build-guidelines asked the constitution-builder to emit the table — but the constitution-builder, by its own contract, emits no routing/diagnostic table at all (that ownership was deliberately removed; see divergence-adjacent item #5 in §02). So the table fell into a gap between the two tools: each assumed the other carried it, and neither did.

The risk that created, and what catching it removed: every composed agent would have shipped without its symptom→KB map — defeating the entire purpose of the cohort, even on a perfectly well-formed manifesto. Catching it removed a silent capability-gut.

Why the outcome is acceptable: build-guidelines now carries the manifesto's table itself, verbatim, into the composed agent rather than delegating it to a tool that's contractually forbidden to produce it. Re-verified through the integration review.

▶The resume-safety guard, as first written, would have silently swallowed a deliberately re-run story's fresh findings — so a resumed build would read stale results and miscount.
Resume idempotency for the build ledger · conduct-ledger-append-site-dedup-guards

What this part does: when a conduct build is interrupted and resumed, this guard stops the engine from appending the same finding row twice to its durable ledger — the record the end-gate scorecard (this report) is computed from. It keys "have I seen this before?" on the triple (story_slug, event, finding_id).

Why we wrote a guarantee around it, and why that way: a build ledger that double-counts on resume corrupts every number a human is shown at the gate. So the guarantee has two halves that are easy to get into tension: a resumed build must append nothing duplicate, yet a deliberately re-run story must still append its fresh events. The contract was written to hold both at once.

Where reality diverged: because finding ids are deterministic, a re-run story regenerated the same ids as the prior session — so the guard mistook the re-run's genuinely-new events for duplicates and suppressed them. The "append fresh on re-run" half of the guarantee was quietly broken by the very mechanism protecting the "don't duplicate on resume" half.

The risk that created, and what catching it removed: a resumed build would have read stale dispositions and under-counted findings — presenting a falsely-clean scorecard at exactly the moment a human relies on it being honest. Catching it removed a silent miscount.

Why the outcome is acceptable: a RE-RUN KEY CLEARING step at reconcile was added — it clears the prior-session keys for a story that's being re-run, so its fresh events append while a plain resume still deduplicates. Re-verified by the IS-2 integration trace across both cases.

▶A specification cited architecture options and a requirement phrase that don't exist in the sources, and recommended a fix that had already been made — false provenance that would have propagated downstream.
Citation integrity · constitutionmd-generation-acceptance-criteria

What this part does: this is the acceptance-criteria item — the quality bar for generated constitutions. Among its criteria is citation integrity: that anything the standard claims a source says is actually in that source.

Why we wrote a guarantee around it, and why that way: downstream items read this standard as ground truth. A wrong citation here doesn't stay local — it gets quoted, re-quoted, and trusted by everything that builds on it. So the guarantee insists every cited claim be checkable against the real source, precisely because false provenance compounds.

Where reality diverged: the item as first written quoted architecture "options" and a phrase attributed to requirement FR136 that don't appear in the sources, and it recommended amending prd.md — a change that had already been made (FR136 is already annotated against DEC-038). The standard was asserting things its own sources didn't say.

The risk that created, and what catching it removed: downstream items would have inherited invented provenance and a redundant "fix" instruction, eroding trust in the whole citation chain. Catching it removed propagating false provenance at the root.

Why the outcome is acceptable: the reviewer checked the actual sources, removed the non-existent quotes, corrected the FR136 claim, and dropped the already-done prd.md recommendation. The standard now cites only what its sources really contain.

▶The conductor's own end-gate scorecard would have over-counted findings on a resumed build, because the "this finding supersedes an earlier one" rule wasn't applied to the auto-fixed and dismissed tallies.
Scorecard supersession · conduct end-gate tallies (caught at AVFL)

What this part does: when conduct assembles the numbers you see at the top of this report, a supersession rule says that if a later finding replaces an earlier one, only the later should be counted — otherwise resumed or re-run builds inflate their own totals. "AVFL" is the post-merge adversarial review pass that looks at the whole merged stack at once.

Why we wrote a guarantee around it, and why that way: the scorecard is the one artifact a human reads to decide whether to approve. If it inflates its own counts, the human is making a real decision on fabricated arithmetic — so supersession must apply everywhere a count is formed, not just in one place.

Where reality diverged: supersession was applied to story membership but not to the auto-fixed and dismissed tallies — so on a resumed build, those two counts would over-report.

The risk that created, and what catching it removed: the headline "auto-fixed" and "waved-off" numbers could read higher than reality on any resumed build, subtly misrepresenting the build's state at the exact moment it matters most. Catching it removed an inflated scorecard.

Why the outcome is acceptable: supersession is now applied to both the auto-fixed and dismissed counts as well as to story membership, so the tallies match the true post-supersession set. Caught and fixed at the AVFL integration pass.
