00The frame these loops live in

Non-negotiable
Every loop must reach a terminal state on its own — clean, a score threshold, or a cap. A workflow cannot pause to ask a human, so "ask the developer" is never a loop exit. Unresolved state becomes residual data the end-of-run HITL report surfaces.

Three loops, one shared control kit. Each loop is a pure function over its inputs that returns a structured result; the execution workflow composes them with pipeline (per-story, no barrier) and sequential phases (sprint-level). All caps below are starting defaults — tune later.

01qaReviewFixLoop — per story, pre-merge

Runs as the second stage of pipeline(stories, dev, qaReviewFixLoop) — one per story, no barrier

QA and code-review run in parallel against one freshly-developed story in its worktree; findings drive fix agents; re-verify; repeat until clean or capped.

async function qaReviewFixLoop(built, { maxRounds = 3 } = {}) {
  let round = 0
  while (true) {
    // QA ∥ review — barrier here is fine: both gate the SAME story
    const [qa, review] = await parallel([
      () => agent(qaPrompt(built),     { agentType: 'momentum:qa-reviewer', phase: 'QA·review', schema: FINDINGS }),
      () => agent(reviewPrompt(built), { agentType: built.devAgent, phase: 'QA·review', schema: FINDINGS }),
      //                          ↑ code-reviewer is a SKILL, not an agentType — see §07.
      //                            run it via a dev/Explore agent told to Skill(momentum:code-reviewer).
    ])
    const findings = [...(qa?.findings ?? []), ...(review?.findings ?? [])]
      .filter(f => f.severity !== 'nit')            // don't loop on cosmetics

    if (findings.length === 0)  return { slug: built.slug, status: 'clean', rounds: round }
    if (round >= maxRounds)   return { slug: built.slug, status: 'capped', rounds: round, residual: findings }

    round++
    // fixes are SEQUENTIAL within a worktree — parallel writes to one tree race
    for (const group of groupByFile(findings)) {
      await agent(fixPrompt(built, group), { agentType: built.devAgent, phase: 'Fix' })
    }
    // loop re-verifies the fixes
  }
}
TERMINATESClean exit OR round >= maxRounds. No path loops without incrementing round.
null-safeqa?.findings ?? [] — a crashed/skipped agent resolves to null, never throws.
no-oscillationSeverity filter + hard cap bound the case where a fix introduces a fresh finding each round.
write-raceFixes serialized per worktree; the QA∥review barrier is intra-story only, so it doesn't stall other stories.

Why a barrier is OK here (despite "default to pipeline"): QA and review both gate the same story and must both finish before the fix decision. The no-barrier win is at the pipeline level above — story B's loop runs while story A's is still iterating.

02e2eValidateFixLoop — sprint, post-merge · replaces TeamCreate

Runs once on the integrated sprint branch, after merge + AVFL

The e2e-validator checks live behavior against verification-harness.json; FAIL scenarios spawn fixes; re-validate; repeat. The cross-agent context TeamCreate used to carry becomes a structured handoff passed into the validator's prompt.

async function e2eValidateFixLoop({ sprint, specDeltas }, { maxRounds = 2 } = {}) {
  let round = 0
  while (true) {
    const report = await agent(e2ePrompt(sprint, specDeltas), {
      agentType: 'momentum:e2e-validator', phase: 'E2E', schema: E2E_REPORT,
    })

    // BLOCKED = harness/env down. Terminal NON-failure — looping can't fix infra.
    if (report.verdict === 'BLOCKED')
      return { status: 'blocked', why: report.blockedReason, rounds: round }

    const failures = report.scenarios.filter(s => s.result === 'FAIL')
    if (failures.length === 0) return { status: 'clean', rounds: round }
    if (round >= maxRounds)  return { status: 'capped', rounds: round, residual: failures }

    round++
    // failures touch different files → fixes can run in parallel (barrier OK, all gate re-validate)
    await parallel(failures.map(f => () =>
      agent(fixPrompt(f), { agentType: f.owningDevAgent, phase: 'E2E·fix' })))
    // specDeltas re-passed next round — structured handoff, not TeamCreate chatter
  }
}
TERMINATESThree exits: clean, capped, or BLOCKED. BLOCKED is the key one — without it, an env outage loops forever.
handoff > chatterspecDeltas (what changed vs. the spec) is injected into the validator prompt — replaces the inter-agent messaging TeamCreate provided.
low cap2 rounds — e2e is expensive; residual failures go to the report, not endless retry.
no pytest fallbackValidator prompt forbids substituting unit tests for live behavior (carry the existing rule verbatim).

Why this beats TeamCreate: e2e never needed agents talking — it needs validate → fix → re-validate. Deterministic, resumable, no coordination overhead, and BLOCKED is handled explicitly instead of stalling a team.

03avflLoop — sprint, post-merge · AVFL-as-Workflow

Wraps the existing momentum:avfl sub-skills as a workflow, retargeted at the 3-dot merged git result (the integration surface)

This is Momentum's real AVFL — not a discovery loop. Dual-reviewer lenses → consolidate to a weighted score → fix in severity order → re-validate with declining skepticism. It exits on a score threshold (or an iteration cap), never on "nothing new."

async function avflLoop({ integrationSurface, acs }, { threshold = 95, maxIters = 4 } = {}) {
  if (!integrationSurface) return { status: 'clean', score: 100, iters: 0, note: 'disjoint — nothing to integrate' } // OQ#4
  let iter = 0, history = []
  while (true) {
    iter++
    const skepticism = iter === 1 ? 3 : 2          // high first pass, then low — FLOOR is 2
    // 4 lenses × { Enumerator sonnet/med, Adversary opus/high }, all parallel (dual review)
    const reviews = await parallel(LENSES.flatMap(L => [
      () => agent(enumPrompt(L, integrationSurface, acs, skepticism), { model: 'sonnet', phase: 'AVFL', schema: FINDINGS }),
      () => agent(advPrompt (L, integrationSurface, acs, skepticism), { model: 'opus',   phase: 'AVFL', schema: FINDINGS }),
    ]))
    // consolidate: confidence (both→HIGH / one→MEDIUM), dedup, drop no-evidence findings
    const { findings, score } = consolidate(reviews.filter(Boolean))
    //   score = 100 − Σ( critical −15, high −8, medium −3, low −1 )
    history.push(score)

    if (score >= threshold) return { status: 'clean',     score, iters: iter, history }
    if (iter  >= maxIters)  return { status: 'max_iters', score, iters: iter, history, residual: findings }

    // fix in severity order; carry ORIGINAL acs/source forward UNCHANGED each iteration
    await agent(fixPrompt(findings), { agentType: codeFixer, phase: 'AVFL·fix' })
  }
}
TERMINATESscore >= 95 (CLEAN) OR iter >= 4 (MAX_ITERATIONS_REACHED). Two independent stops.
declining skepticismIter 1 = high (3); iter 2+ = low (2). Floor is 2 — skepticism 1 collapses Enumerator + Adversary into one reviewer.
score, not zero-defectPass = 95/100, not "no findings." Low-severity residue is acceptable; the weighted score is the gate.
source carried forwardEvery iteration re-validates against ORIGINAL acs/source — never the intermediate fixed output. And Phase 1 always RE-SPAWNS reviewers (no inline validation).
Corrected from the first draft My earlier "loop-until-dry / dedup-vs-seen" was a generic discovery pattern, not Momentum's AVFL. Real AVFL scores each pass (100 − weighted severity), exits at ≥ 95 or 4 iterations, and steps skepticism 3 → 2. The sprint use is the full profile retargeted at the merged integration surface; if integrationSurface is empty (disjoint stories), short-circuit to CLEAN and log the skip (open question #4).

Reuse, don't reinvent (roadmap item 5): wrap the existing momentum:avfl sub-skills (validator-enum, validator-adv, consolidator, fixer) — integration findings route to code-fixer. The benchmark avfl-declining variant steps skepticism down further each iteration (min 1) — a tunable, not the canonical default, which floors at 2.

04loopControlKit — shared primitives

Every loop reuses the same termination + safety predicates. Centralize them so all three behave identically.

// Hard floor below which we stop spending and bank residual for the report.
const BUDGET_FLOOR = 50_000

const budgetExhausted = () => budget.total && budget.remaining() < BUDGET_FLOOR

// Round/score-based loops share this: clean OR capped OR out of budget. Never "ask a human".
const shouldStop = (clean, round, cap) =>
  clean || round >= cap || budgetExhausted()

// Failure becomes POLICY (a workflow can't ask): one retry, then mark + continue.
async function withRetry(thunk, label) {
  const first = await thunk().catch(() => null)
  if (first) return first
  log(`retry: ${label}`)
  const second = await thunk().catch(() => null)
  return second ?? { status: 'failed', label }   // surfaced in the report, never thrown
}
Termination kindsQA/e2e use round caps + clean; AVFL uses a score threshold + iteration cap. All bounded, none human-gated.
Budget guardGuarded on budget.total being set — else remaining() is Infinity and the guard is a safe no-op.
Single retryOne re-spawn on crash, then mark failed and continue — no infinite retry, no human prompt.
Concurrency~16 concurrent / 1000 total are runtime caps; parallel over N reviewers/findings queues safely beyond 16.

05resultAggregation — loops → one data model → the report

Each loop returns structured data; the execution workflow folds it into one SprintResult, which the report-builder agent renders into the HITL HTML. This is the bridge from autonomous loops to the single human gate.

StoryResult = {
  slug, devAgent, status: 'clean'|'capped'|'failed', rounds,
  residualFindings: [{ severity, file, what, why }], commits: [sha]
}

SprintResult = {
  stories:  [StoryResult],
  merge:    { merged: [slug], conflicts: [{ slug, files }] },   // conflicts = human's job
  avfl:     { status: 'clean'|'max_iters', score, iters, history, residual: [finding] },
  e2e:      { status: 'clean'|'capped'|'blocked', residual: [scenario], why? },
  failures: [{ slug, label }]                                   // surfaced TOP of report
}
  • Conflicts & failures lead the report. They're the only things that truly need the human; everything else is FYI + approve/request-changes.
  • The report-builder is the workflow's final stage — agent(reportPrompt(template, sprintResult), {agentType: …}) renders SprintResult against the (charset-fixed) conduct report template.
  • Residuals are first-class. A capped round-loop or a max_iters AVFL isn't a failure — it's "we hit the limit, here's what's left at score N," which the human approves, defers, or sends to an encore.

06Observability + resume

  • phase() / log() per loop step — phases QA·review, Fix, E2E, E2E·fix, AVFL, AVFL·fix make /workflows show live loop progress (which round/iteration, which story, AVFL score history).
  • Resume is cheap for analysis, dangerous for mutation. Pure analysis agents (QA, review, validate, AVFL reviewers) replay from cache on resumeFromRunId. Git-mutating steps (fix-commit, merge) are not safely cacheable.
  • Idempotency rule. Any step that mutates the worktree/branch must check-before-act (is this fix already applied? is this branch already merged?), or — preferred, per the handoff's "Conductor owns all git mutation" — keep merges in the Conductor (skill), not the resumable workflow, so a resumed run can't double-merge.

Correctness flag — must carry into implementation

code-reviewer, avfl, and architecture-guard are SKILLS, not Agent-tool agent types. You cannot pass them as agentType.
